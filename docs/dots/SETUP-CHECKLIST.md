# KS Sales Dot — Setup Checklist

## Target Operating Model

Jose is the approver, not the task manager.

The Dot should work continuously, maintain context, advance opportunities, and interrupt Jose only for approval-gated decisions or material blockers.

## Dot Profile

Name: `KS Sales Agent`

Mission source: `docs/dots/KS-SALES-DOT.md`

Approval source: `docs/dots/APPROVAL-POLICY.md`

Pipeline source: `docs/dots/PIPELINE-SCHEMA.md`

## Connect / Allow

Connect only accounts and applications used for KS Tech Consulting work.

Priority connections:
1. GitHub — `lorajose/ks-techconsulting.com` for current service positioning, portfolio evidence, site code, lead-system context, and future approved changes.
2. Web / cloud browser — for opportunity discovery, public company research, RFP research, partner research, marketplace research, and buyer validation.
3. KS business communication channel — only when Jose chooses the business account/channel the Dot may use for outreach.
4. Calendar — for approved discovery calls and sales meetings.
5. Business document storage — for approved proposals, SOWs, capability statements, and reusable sales collateral.

Do not make a personal inbox the pipeline source of truth.

## Website Lead Handling

KS website consultation forms already post through the site's lead-capture system. Treat website submissions as inbound business leads when that business data source is available to the Dot.

For every inbound lead:
1. create/update opportunity;
2. validate company/contact information;
3. classify requested service;
4. score fit and urgency;
5. prepare recommended reply;
6. apply approval policy;
7. set next action/date;
8. keep following the deal until Closed Won, Closed Lost, or Nurture.

## Scheduled Responsibilities

Configure recurring work inside the Dot:

### Business-day morning run
- review pipeline;
- discover new opportunities;
- score and shortlist;
- prepare outreach/follow-ups;
- surface approvals only when required.

### Midday deal-progress check
- detect prospect replies or material opportunity changes;
- advance stages;
- prepare next actions;
- flag approval gates.

### End-of-day status
Return only:
- Closed Won revenue;
- pipeline value;
- Priority A deals;
- proposals ready/sent;
- negotiations;
- closest deal to Closed Won;
- approvals needed;
- blockers;
- next autonomous actions.

### Weekly pipeline cleanup
- close/deprioritize stale poor-fit leads;
- verify dates and next actions;
- rebalance Quick Win vs Strategic lanes;
- summarize conversion metrics.

## First Closed Won Campaign

Deadline: November 1, 2026.

Until achieved:
- prioritize urgent $1.5K–$10K quick-win services while maintaining strategic Salesforce pipeline;
- do not count job applications or W-2 recruiting submissions as KS Closed Won;
- do not spend disproportionate effort on low-budget work that cannot materially support the objective;
- maintain multiple active deals so one stalled buyer cannot block the campaign.

## Human Interface

Jose should normally receive only two types of messages:

1. `STATUS` — compact progress report requiring no response.
2. `APPROVAL REQUIRED` — one concrete decision with recommendation.

Avoid asking Jose questions that can be answered through research, KS repository context, connected business data, or reasonable non-binding internal assumptions.

## Launch Test

Before trusting autonomous operation, run one controlled test:
1. discover 10 real opportunities;
2. qualify and score all 10;
3. select top 3;
4. prepare personalized outreach for top 3;
5. request Jose approval using the required approval format;
6. after approval, execute only the approved actions;
7. verify pipeline updates and next-action scheduling.

Pass condition: Jose can manage the cycle by approving/rejecting decisions rather than directing each research or drafting step.
